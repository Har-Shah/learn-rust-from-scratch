# Lesson 0.2 — Crate anatomy, your tools, and your first commit

**~30 minutes. Stopping point at the end.**

## What we're doing and why

You have a crate that doesn't compile and a repository with nothing committed. By the end of this
lesson both are fixed, and you'll have met the two tools Rust programmers run constantly.

This is deliberately a *tooling* lesson, not a language lesson. Mutability gets taught properly in
1.1 — here you're just going to apply the fix the compiler already handed you, so there's something
green to commit.

## The three files `cargo new` left you

### `Cargo.toml` — the manifest

```toml
[package]
name = "foundations"
version = "0.1.0"
edition = "2024"

[dependencies]
```

Roughly `pyproject.toml`. The interesting line is `edition`.

An **edition** is an opt-in generation of Rust — 2015, 2018, 2021, 2024. Editions let the language
make changes that would otherwise break existing code: new keywords, changed defaults. Your crate
declares which generation it's written in, and the compiler adapts.

The part that matters: **crates on different editions work together fine.** A 2024 crate can depend
on a 2015 crate. This is how Rust has avoided a Python 2 → 3 split — there is no flag day, because
the unit of migration is a single crate rather than the whole ecosystem.

### `Cargo.lock` — the exact versions

You didn't write this; cargo generated it. `Cargo.toml` says what you *want* ("some 1.x version of
this crate"). `Cargo.lock` records what you actually *got*, pinned exactly, so the same build
happens on any machine on any day. Closest Python equivalent: `poetry.lock`.

Yours is nearly empty right now — you have no dependencies. It will grow.

**Commit it or not?** The rule: **binaries commit `Cargo.lock`, libraries traditionally don't.** A
binary is something people run, and you want everyone building it to get an identical result. A
library is something people depend on, and its consumers should be free to pick their own
compatible versions. `foundations` is a binary. Commit it.

### `target/` — build output

Everything cargo produces. Regenerable from source, and large. Already gitignored.

## The two tools you'll run constantly

**`cargo fmt`** — the standard formatter. Rust culture treats formatting as settled rather than a
matter of taste, which sounds authoritarian and turns out to be a relief: nobody argues about braces
in code review because there's nothing to argue about.

**`cargo clippy`** — a linter with roughly 700 lints, and a genuinely different job from the
compiler. Where `rustc` asks *"is this a valid program?"*, clippy asks *"is this a good one?"*

The distinction matters:

```rust
if name.len() == 0 {
```

`rustc` has no complaint — that's a perfectly valid program. Clippy will tell you to write
`name.is_empty()` instead. Both compile; one is clearer and won't trip over the difference between
a string's byte length and its character count (a distinction that will matter a great deal in
Lesson 1.6).

Clippy is where a lot of idiomatic Rust gets learned. Read its suggestions rather than just applying
them.

## Predict before you run

**Q1.** You'll run `cargo clippy` on code that compiles with no warnings at all. Do you expect it to
find anything? Why would a second tool have anything to say about code `rustc` was happy with?

**Q2.** Right now `git status` will list untracked files. Predict which of these appear:
`Cargo.toml`, `Cargo.lock`, `src/main.rs`, `target/`, `reader.html`, `lessons/`.

## Your task

**Acceptance criteria:**

1. `cargo run` prints both lines with no errors
2. You've run `cargo fmt` and `cargo clippy` and read what they said
3. Everything that should be tracked is committed; everything that shouldn't, isn't
4. You can explain why clippy flagged what it flagged

### 1. Get to green

Open `foundations/src/main.rs`. The compiler already told you the fix in its `help:` line — apply
it. Don't overthink this one; understanding *why* is Lesson 1.1's job.

```bash
cargo run
```

Both lines should print.

### 2. Meet clippy

Replace `main.rs` with this — it compiles cleanly, and `rustc` will say nothing:

```rust
fn main() {
    let name = String::from("ferris");
    if name.len() == 0 {
        println!("empty");
    } else {
        println!("hello {name}");
    }
}
```

```bash
cargo run
```

```bash
cargo clippy
```

Read the lint carefully — the name, the explanation, and the `help` line. Then fix it as clippy
suggests and run `cargo clippy` again until it's silent.

### 3. Formatting

Deliberately mangle the indentation — add stray spaces, put a brace somewhere ugly. Then:

```bash
cargo fmt
```

Look at the file again.

### 4. Your first commit

```bash
cd ~/Learning && git status
```

Compare against your Q2 prediction before doing anything else.

```bash
git add -A && git status
```

Check the staged list. **If `target/` or `reader.html` appear, stop and tell me** — that means a
gitignore isn't working, and committing build output is much easier to prevent than to undo.

Then commit. Write the message yourself — describe *what changed and why*, not "first commit".
