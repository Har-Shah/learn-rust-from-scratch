# Lesson 0.1 — The compilation model, and reading your first error

**~30 minutes. There is a stopping point at the end — don't continue past it.**

## What we're doing and why

Before writing any Rust, you need one mental model that Python never required of you:
**Rust checks your entire program before it produces anything runnable.**

In Python, `python app.py` hands your source to an interpreter that executes it line by line. A
misspelled variable on line 500, inside a branch that only runs on leap years, is a perfectly valid
Python file. It ships. It fires at 3am in February 2028.

In Rust, `cargo run` does something different:

```text
your source  ──rustc──>  checks EVERY path  ──>  binary  ──>  runs
                              │
                              └─ if anything is wrong: NO BINARY IS PRODUCED
```

That last part is the whole point. A Rust program with an error doesn't produce a broken executable
— it produces *no executable*. There is nothing to deploy.

This is why Rust programmers describe the compiler as a collaborator rather than an obstacle: you
are trading time now for a category of 3am pages you will never receive.

It matters immediately for our app. By Stage 5 you'll have a web server with many routes.
Understanding *when* Rust catches things determines how you build and deploy it.

## The concept you need: how to read a rustc error

Rust's error messages are unusually good, and they follow a consistent structure. Learning to read
them is a real skill — I'm teaching it first, because you will read hundreds.

```text
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("x is {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++
```

Five parts, each doing a distinct job:

| Part | What it gives you |
|------|-------------------|
| `error[E0384]` | A **stable error code**. Look it up with `rustc --explain E0384` for a full page with examples. Most people never discover this command. |
| `cannot assign twice...` | The one-line summary |
| `--> src/main.rs:4:5` | File, line, column |
| The `\|` block | The **spans**. `^^^^` marks where it went wrong; `-` marks the earlier code that caused it. Rust shows you *both ends* of the problem. |
| `help:` | A suggested fix, often with the exact characters to add (`+++`) |

**The habit worth building:** read the spans *before* the help text. The `help` line tells you what
to type; the spans tell you what Rust was thinking. Only one of those transfers to the next error.

### Steps

```bash
cd ~/Learning && git init
```

```bash
rustc --version && cargo --version && rustfmt --version && cargo clippy --version
```

```bash
cargo new foundations
```

**Before running anything**, open the three generated files and read them. They're short.

- `foundations/Cargo.toml`
- `foundations/src/main.rs`

**Notice what is *missing*:** there is no `foundations/.gitignore`, even though `cargo new` usually
writes one.

`cargo new` only creates a `.gitignore` when it also initialises a git repository. Because we ran
`git init` in `~/Learning` first, cargo detected it was already inside a repo, declined to nest a
second one, and skipped the `.gitignore` along with it.

That absence is worth more than the file would have been. Cargo inspected its environment and
adapted, rather than blindly scaffolding. The ignore rule that matters — `target/` — lives in the
repo-root `.gitignore` instead.

**Why ignore `target/` at all?** Look at its size after your first build:

```bash
du -sh foundations/target
```

Everything in it is regenerated from your source. Committing build output means a bloated repo full
of conflicts over files nobody reads.

```bash
cd foundations && cargo run
```

Now break it deliberately. Open `foundations/src/main.rs` and replace its contents with exactly
this:

```rust
fn main() {
    let x = 5;
    println!("x is {x}");
    x = 6;
    println!("x is now {x}");
}
```

```bash
cargo run
```

Then look up the code it gives you:

```bash
rustc --explain E0384
```

**Do not fix the error.** Reading it is the exercise.
